01
Metadata Consolidation: Single JSON vs. Multiple Sidecars
▼
The Core Tension
Ensuring transactional data updates and race-condition elimination during concurrent runs vs. maintaining simple, modular, text-based metadata outputs.
ET
Dr. Evelyn Thorne Lead Architect
Our v1 design generated separate sidecars (`clean_meta.json`, `print_meta.json`). This created massive race conditions when stages executed concurrently. A consolidated `.meta.json` with namespace separation (`input`, `quality`, etc.) and a locker helper (`meta_helper.py`) utilizing file-level locking ensures that write conflicts are impossible.
KA
Ken Allred Lead Developer
I like having a single file to read inside the Unity/Unreal editors. My only concern is crash safety. If the cleanup module crashes, does it corrupt the metadata written by the generation step?
ET
Dr. Evelyn Thorne Lead Architect
No. The `meta_helper.py` script performs field-level merges rather than full overrides. It locks the file, reads it, updates only its designated namespace, validates it against `meta_schema.json`, and writes it back. It leaves other namespaces untouched.
✔ Verdict & Architecture Approved

Consolidated metadata schema is implemented. All scripts must merge their outputs via `scripts/meta_helper.py` utilizing the schema validation contract.

02
Conditional Background Removal: Auto vs. Forced Execution
▼
The Core Tension
Applying high-quality pre-processing to eliminate background geometries vs. avoiding execution time overhead (2-3s) and destructive segmentation errors on complex shapes.
KA
Ken Allred Lead Developer
Background removal is the most important preprocessing step. If a designer inputs a photo with a shadow, the shadow becomes part of the 3D mesh. We need `rembg` active by default.
JM
Jax Mercer Systems Engineer
Wait. Running `rembg` takes 2 to 3 seconds on an Apple Silicon laptop. If the input image is already a transparent PNG or a clean studio shot with white backgrounds, we are wasting power. More importantly, `rembg` can segment out thin geometry, like antennas or wires, completely ruining the asset without warning.
ET
Dr. Evelyn Thorne Lead Architect
A conditional approach is best. We run a background uniformity check first. If it's above 0.85 or already alpha-mapped, we skip `rembg`. We also check the output. If the foreground coverage drops below 5%, the background removal was likely destructive; we fall back to the original image and log a warning.
✔ Verdict & Architecture Conditional Auto

Configure `--bg-removal auto` as the default. Allow manual overrides via `on` or `off` flags for edge cases.

03
Hunyuan3D-Paint Integration: Licensing & Commercial Risk
▼
The Core Tension
Adding state-of-the-art PBR texture generation to improve asset visual quality vs. legal compliance limits of the Tencent Hunyuan Community License.
KA
Ken Allred Lead Developer
We are building commercial games. The basic texture upscalers look flat. Hunyuan3D-Paint generates realistic normals, roughness, and metallic maps. We need to ungate the deliberate error stub in `scripts/texture.sh`.
CV
Clara Vance Legal Counsel
The Tencent Hunyuan Community License permits commercial use of generated outputs. The primary catch is that if a product using outputs exceeds 100 million Monthly Active Users (MAU), a separate commercial agreement is required. There are also standard exclusions for military use and illegal content.
KA
Ken Allred Lead Developer
If our indie games hit 100 million active users, paying Tencent for a commercial license is a minor problem we'd love to have. For now, it's virtually a free pass.
✔ Verdict & Architecture Approved (Threshold)

Hunyuan3D-Paint approved under `commercial_threshold` bucket. The stub is removed, and all textured assets will record their license status in the metadata log.

04
ComfyUI 2D Backend Integration: Option A (Direct Backend)
▼
The Core Tension
Supporting visual character identity consistency across poses vs. managing massive dependency stacks and separate Python environment overheads.
KA
Ken Allred Lead Developer
We cannot generate character assets as one-offs; we need identity consistency. If we create a weapon set, they must match. We need SDXL + ControlNet + IP-Adapter, which ComfyUI supports headlessly.
JM
Jax Mercer Systems Engineer
ComfyUI requires a completely different version of Torch and conflicts with libraries in our main pipeline. If we try to combine them, the installer will fail or overwrite dependencies.
ET
Dr. Evelyn Thorne Lead Architect
We will implement Option A. ComfyUI is added as a separate 2D backend, isolated in its own `comfyui-env/` directory. It remains completely optional. Default generations still run fast via `mflux`. We also enforce the consistency pack manifest format in `docs/consistency-pack-format.md` to cleanly separate assets.
✔ Verdict & Architecture Approved (Isolated Venv)

Option A is selected. ComfyUI runs inside a separate environment, triggered only by the `--backend comfyui` flag.

05
Multi-View 3D Backend Selection: TRELLIS vs. OpenLRM vs. InstantMesh
▼
The Core Tension
Achieving superior 3D structural reconstruction from multiple angles vs. complying with licensing limitations (non-commercial or proprietary).
CV
Clara Vance Legal Counsel
InstantMesh is disqualified immediately due to Tencent license issues. TRELLIS has a non-commercial code license, which is unsafe for *Grithkin*. OpenLRM is Apache 2.0 and fully commercial-safe.
KA
Ken Allred Lead Developer
Wait. OpenLRM's reconstruction quality is significantly lower in our initial tests compared to TRELLIS. If the assets look bad, we cannot ship them anyway. We must measure them objectively.
ET
Dr. Evelyn Thorne Lead Architect
We have checking tools in `scripts/multiview_benchmark.py`. We will run OpenLRM, TRELLIS, and InstantMesh against a test suite of humanoid, mechanical, and organic subjects. If OpenLRM's score is above 6.5, we use it. If not, we fall back to TRELLIS for prototyping, while parallel-tracking a license review for InstantMesh.
✔ Verdict & Architecture Awaiting Data

Run benchmark using `multiview_benchmark.py`. Default to OpenLRM for commercial distribution if it passes; fallback to TRELLIS for local prototyping only.

06
Turntable Preview Gating: GIF Render Costs on Laptop vs. Studio
▼
The Core Tension
Providing interactive visual validation for designers vs. wasting CPU/GPU runtime on local laptops (3-6s per asset).
JM
Jax Mercer Systems Engineer
Rendering a 12-frame turntable GIF at 8 FPS takes about 4 seconds on a laptop. If a user runs batch generation, this delays the queue dramatically and causes thermal throttling.
KA
Ken Allred Lead Developer
But visual inspection is critical. I can't check for mesh gaps or backside distortion in a single static frame. I need to see it spin.
ET
Dr. Evelyn Thorne Lead Architect
We will make this tier-conditional using the `hardware_tier` function. On the Studio tier, the GIF is default-on. On the Laptop tier, we generate only a static hero PNG (<0.2s) by default, and make the GIF generation an opt-in flag.
✔ Verdict & Architecture Tier Gated

Gated turntable GIF to opt-in on laptop tier. Studio tier retains default-on spinning GIF. Static hero PNG remains default for both.

07
Watertight Mesh Verification: Warning vs. Strict Blocking
▼
The Core Tension
Preventing physical print failures and wasted plastic vs. allowing slicer auto-recovery and flexible testing.
KA
Ken Allred Lead Developer
If we block export just because a model has a single open boundary edge, it will break our automated asset runs. Slicing software like Cura can repair minor holes anyway.
ET
Dr. Evelyn Thorne Lead Architect
We must not block, but we must report. The watertight checks will write details (hole count, boundary count) to the metadata file under `quality.manifold`. The user-facing tool will warn the user with translated, human-friendly terms rather than technical jargon.
✔ Verdict & Architecture Warn Only

The print check will warn the user about non-manifold geometry, but only block if the model physically exceeds build plate bounds (270mm).

08
CLIP Consistency Metric: Soft Signal vs. Hard Threshold Gating
▼
The Core Tension
Enforcing semantic consistency between input images and 3D outputs vs. accounting for style variance and subjective prompts.
ET
Dr. Evelyn Thorne Lead Architect
We want a machine metric to verify 3D reconstruction quality. Comparing the 3D model render to the original input image via open_clip ViT-L/14 seemed like an ideal gating criteria. We planned to block models scoring below 0.80.
KA
Ken Allred Lead Developer
A hard threshold is highly problematic. CLIP scores vary wildly depending on whether the asset is a simple voxel shape, line art, or a photo. A cartoon character might score 0.72 and look great, but a noisy mess might score 0.82. We shouldn't fail runs based on this.
JM
Jax Mercer Systems Engineer
Running CLIP also demands extra memory. We should treat it as an advisory metric for ranking variants, rather than a hard fail gate.
✔ Verdict & Architecture Advisory Metric

CLIP score is designated as a soft signal. We write it to metadata and warn if it falls below 0.75, but never abort the pipeline run.

09
Environment Consolidation: Single Shared venv vs. Multiple venvs
▼
The Core Tension
Saving local disk storage space (15GB vs 6GB) vs. avoiding library dependency conflicts.
JM
Jax Mercer Systems Engineer
Installing separate Python environments for `rembg`, CLIP, and mesh tools takes over 15 GB of disk space due to duplicated PyTorch libraries. Consolidating into a single `pipeline-tools-env` saves about 9 GB on developers' laptops.
ET
Dr. Evelyn Thorne Lead Architect
Consolidating PyTorch is complex because different packages require different sub-versions. However, after auditing the requirements, we confirmed `rembg`, `open_clip_torch`, and `trimesh` can run cleanly on a shared Torch 2.x environment. ComfyUI is the only library that remains isolated.
✔ Verdict & Architecture Consolidated

Approved unified venv `pipeline-tools-env/`. ComfyUI stays isolated to prevent configuration drift.
